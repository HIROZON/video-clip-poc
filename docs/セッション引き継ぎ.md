# AIクリッピングメーカー MVP - セッション引き継ぎ

最終更新: 2026-07-28

---

## 1. コンセプト

海外サービス（OpusClip）のコピーではなく、**日本企業向けのAI動画運用プラットフォーム**を目指す。

「編集するAI」ではなく「**投稿できる状態まで完成させるAI**」を提供する。

体験：URLを貼るだけ → AIが最適なショート動画を複数生成 → そのまま投稿できる

### ターゲット（当初案）
中小企業 / 採用担当 / SNS運用担当 / マーケティング担当 / セミナー・講演運営 / 動画制作会社

### MVP成功条件
URLを貼る → 用途を選ぶ → AI生成 → ダウンロード → そのまま投稿、の4ステップで完結すること。

### 差別化ポイント（海外クリッピングAIとの違い）
- 用途ベース解析（1問だけの質問：「この動画は何に使いますか？」）
- AI理由表示（なぜこの候補を選んだか）
- 業務スコア（Virality Scoreではなく、採用/商品PR/SNS等の業務適性評価）
- ブランドDNA（企業ごとのフォント・カラー・ロゴ・CTA保存、次回自動適用）
- 日本語字幕品質（誤変換補正・句読点補正）
- 投稿文生成（タイトル・説明文・ハッシュタグ・CTA）

MVPで実装しない機能：API、チーム管理、承認フロー、SNS自動投稿、多言語翻訳、Bロール生成、AI画像生成、GIF、絵文字、効果音。

## 2. 競合分析

### 海外系クリッピングAI（OpusClip / Klap / 2short.ai）
- OpusClipは「元動画の分数＝クレジット消費」という課金モデル（クリップ本数ではない）。Starter $15、Pro $29、Businessは要見積もり。60分アップロード＝60クレジット。
- Active Speaker Detection（音声＋動きから話者検出）とReframeAnything（話者追尾リフレーム）を実装済み。ただしレビューでは「アップデートで逆に精度が落ちることがある」との指摘もあり、業界トップでも発展途上。
- 日本語配信の切り抜き文脈では、海外製ツールは日本語の字幕精度が英語ほど高くないとの評価がある → ここが日本市場での参入余地。
- ユーザー不満点：クレジット追加購入の価格表が不透明、返金対応の遅さ、機能の日次上限など。

### 日本の切り抜きAI（KIRARI / キリヌキAI）
- 個人配信者・VTuber切り抜きチャンネル運営が主戦場（他人コンテンツの二次利用、事務所ガイドライン準拠が前提）。
- 御社が狙う「自社コンテンツ×法人利用」とは市場がほぼ重ならない。
- 技術詳細（追尾アルゴリズム等）は公開情報からは確認できず。

### 日本の汎用AI動画編集ツール（Vrew）
- 韓国VoyagerX社開発、日本語話者向けに強い実績（認識精度85〜92%程度）。
- 料金体系（複数情報源で差異あり、要最新確認）：
  - Light: 年額¥12,290（月換算約¥1,024）〜月額¥1,290程度
  - Standard: 年額¥20,990（月換算約¥1,749）〜月額¥2,490程度
  - Business: 年額¥43,000（月換算約¥3,583）〜月額¥7,990程度（情報源により差異）
  - Businessは音声解析7,200分・AI画像6,000クレジット・60GBクラウド等の大容量枠、法人・チーム利用向け
- テキストベース編集（文字起こしを編集すると映像が連動）が軸。「どこを切り抜くべきか」をAIが用途に応じて自動判断し理由を示す、という御社のコンセプトとは設計思想が異なる。

### 隣接領域（NoLang等）
- テキスト/PDF/URL→動画生成という逆方向のアプローチ。60社以上の法人導入実績があり、法人がAI動画に予算を割く土壌は育っている。

### 総合評価
直接競合は不在に近く、「日本語×B2B×用途特化」の切り口自体の勝算は高い。ただしカテゴリ名を「切り抜きAI」にすると価格比較に巻き込まれるため、「動画運用AI」という当初のポジショニングが重要。**MVPで狙うペルソナを1つに絞ることが勝率を左右する**。

## 3. Phase分けの方針（技術検証の結果を踏まえて確定）

### Phase 1：単一話者・固定/準固定カメラ限定でリリース
- 主戦場：**BtoB企業のウェビナー運用**（最有力）
- 副次的：教育・研修コンテンツ（既存事業の福祉・介護業界の顧客接点との親和性あり）
- 除外（Phase 2送り）：採用面接（面接官＋候補者）、パネルディスカッション、複数ゲストのポッドキャスト

### Phase 2：音声diarization×映像トラッキングによるアクティブスピーカー検出
- 技術検証はResearch機能で並行調査中（pyannote-audio等のOSS vs クラウドAPI比較、日本語精度、コスト）

## 4. 技術検証（人物検出・自動リフレームPoC）結果

リポジトリ: `C:\Users\hashi\Projects\video-clip-poc`（GitHub: HIROZON/video-clip-poc, developブランチ）

### 検証の経緯と結論

1. **モデル選定**：MediaPipe Face Detectionの`blaze_face_short_range`は検出率3.9%と低精度（ウェビナー録画のような中距離・非正面向き被写体に弱い）。`blaze_face_full_range`に切り替えることで検出率26.8%まで改善（約7倍）。
2. **顔検出だけでは不十分と判明**：full_rangeでも検出率は3割弱に留まる。被写体が背中を向ける・横を向く等の自然な動作で顔検出が構造的に失敗する。
3. **Pose Landmarker併用で解決**：顔検出が失敗した93フレーム全件（100%）をPose Landmarker（肩・鼻ランドマーク）で代替検出できることを確認。
4. **統合後の最終結果**：顔検出→Pose Landmarker→直前座標保持、の優先順位ロジックに統合。127フレーム全件を顔検出またはPoseで解決（fallback=0件）。前回フレームアウトしていた2箇所（75%地点・終了間際）も解消。

**結論**：Phase 1（単一話者・固定/準固定カメラ）の技術的実現性は実証済み。ただしサンプルは1本のみのため、条件の異なる動画（照明・被写体との距離等）での再現性確認は未実施。

### 処理速度（ローカルCPU実測）
- 人物検出・リフレーム：24.2秒/出力1分
- 字幕焼き込み（日本語、MS Gothic使用、文字化けなし確認済み）：7.67秒/出力1分
- 合計：31.9秒/出力1分

### 未検証・今後の課題
- 複数の異なる条件（照明・距離・服装等）での再現性確認
- 複数人物が重なるケースでのPose Landmarkerの挙動
- Railwayへの実デプロイでのビルド確認（mediapipe/ffmpegの依存解決）と実際の課金額確認

## 5. 原価実測結果

### ASR・LLM解析（OpenAI API実測、テスト動画1.06分）

| 工程 | 実測値 |
|---|---|
| ASR（Whisper API） | $0.006338（音声63.38秒、$0.006/分） |
| LLM解析（GPT-4o mini、候補抽出+理由+業務スコア） | $0.000270（805+248トークン） |
| 投稿文生成（GPT-4o mini、5クリップ×3プラットフォーム=15回呼び出し） | $0.001717（4,593+1,714トークン） |
| **合計** | **$0.008325（約1.25円）** |

### 映像処理（Railway料金換算：CPU $0.00000772/vCPU秒、RAM $0.00000386/GB秒、1vCPU/1GB想定）

| 工程 | 実測値 |
|---|---|
| 人物検出・リフレーム | 24.2秒/分 → 約0.042円/分 |
| 字幕焼き込み | 7.674秒/分 → 約0.013円/分 |
| **合計** | **31.874秒/分 → 約0.055円/分** |

### 15分動画・5クリップ生成のモデルケースでの原価（実測ベース換算）

| 工程 | 旧試算（推測） | 新試算（実測ベース） |
|---|---|---|
| ASR | $0.12 | 約$0.09 |
| LLM解析 | $0.04 | 約$0.001〜0.003 |
| 投稿文生成 | $0.05 | 約$0.005〜0.01 |
| 人物検出・自動リフレーム | $0.25（原価の44%と想定） | 約$0.001〜0.004 |
| 字幕焼き込み | $0.10 | 約$0.0004（出力5分想定） |
| ストレージ | $0.01 | $0.01（未実測のまま） |
| **合計** | **$0.57** | **約$0.11〜0.12** |

### 重要な発見
- 当初「原価の44%を占める最大コスト要因」としていた人物検出・リフレームは、実測ではほぼゼロコスト。
- 実際のコスト構造は**ASRが7〜8割を占める一強状態**。コスト最適化を検討するならASR（Whisper API以外の選択肢：faster-whisper自前ホスティング等）が唯一意味のあるレバー。
- ただし実測はPoCの単発実行によるものであり、本番運用ではワーカー常時稼働コスト・リトライ・ストレージ/エグレス・サポートコスト等が追加で乗る。**保守的には実測値の3〜5倍程度をバッファとして見るべき**（実効原価目安：¥50〜90/本）。

## 6. 価格設計

### 検討した3パターン

**パターンA（価格競争力重視）**：Starter ¥2,980 / Business ¥9,800。Vrew Businessと同水準で競合。粗利63〜83%。

**パターンB（現行案・価値訴求重視）**：Starter ¥3,000 / Business ¥18,000。Vrewとはカテゴリを分けて訴求。粗利80〜89%。

**パターンC（中間案・原価差分を機能強化に再投資）**：Starter ¥3,980 / Business ¥14,800。Vrewよりやや高いが極端な差はつけず、原価の余剰を日本語字幕品質・カスタマーサクセスに再投資。粗利76〜87%。

### 現在の暫定候補：**パターンC**

推奨理由：
1. Vrewとの価格差が開きすぎると法人稟議で説明コストが増え営業サイクルが長引く
2. 原価の余剰は値下げよりも「日本語品質」「業務特化サポート」というVrewが手薄な領域への再投資の方が長期的差別化になる
3. 過度な値下げはスイッチングコストの低いユーザー層を集めやすく、継続利用の質が下がるリスクがある

未確定事項：Enterpriseプランの具体的な価格、年間契約割引の有無、ストレージ・エグレスコスト実測後の最終調整。

## 8. 開発環境・規約メモ

- 開発環境：VSCode（Claude Codeインストール済み）、Vercel、Neon、Railway、GitHub
- video-clip-pocはPoC/検証目的のリポジトリのため、他プロジェクト（AWRKeeping-app等）のtsc/DB操作規約は適用外。git運用（develop→main等）は同様の考え方を踏襲。
- 実データ（transcript.json、coordinates.json、音声ファイル等、実在人物の発話・映像を含むもの）はリポジトリがpublicのためコミット対象から除外している。
